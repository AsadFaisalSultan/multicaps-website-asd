# Multicaps website

A static website (plain HTML, CSS and JavaScript). It runs on any web host and needs no CMS, database or server-side code.

## Structure

```
index.html, about.html, products.html, ...   built pages (these get uploaded)
blog/                                        Insights index and articles
assets/css/style.css                         all styles
assets/js/main.js                            menu, forms, size chart, gallery, etc.
assets/img/                                  optimised photos, logos, client logos
assets/docs/Multicaps-Company-Profile.pdf    downloadable profile
sitemap.xml, robots.txt                      generated by the build
_build/                                      source for the pages (don't upload)
```

## Editing pages

The header, footer, call-to-action band, client logos, capsule size chart and production steps are shared across pages. They live in `_build/build.py`. Each page's own content is in `_build/pages/*.html`.

After editing, rebuild:

```bash
python3 _build/build.py
```

This rewrites every page and the sitemap in the project root. To add a blog post, copy one of the `_build/pages/blog-*.html` files, change the header block (title, description, path, image) and the content, then add a card for it to `blog-index.html` and rebuild.

## Preview locally

```bash
python3 -m http.server 8080
```

Then open http://localhost:8080.

## Forms

The contact, sample request and careers forms work without a backend: on submit, they open the visitor's email app with the details filled in, addressed to info@multicaps.net.

To have submissions sent directly instead, create a form endpoint (for example with Formspree, Getform or Basin), then put its URL in the form's `data-endpoint=""` attribute in `_build/pages/contact.html`, `request-sample.html` and `careers.html`, and rebuild. CV uploads on the careers form only work with an endpoint.

## Deploying

Upload everything except `_build/` and `README.md` to the web root. Configure the host to serve `404.html` for missing pages. The old WordPress URLs (`/about-us/`, `/hard-gelatin-capsule/`, `/contact-us/`, `/csr/`, `/career/`, `/gallery/`, `/inquiry-form/` and the two `/2025/04/21/...` blog posts) should be 301-redirected to their new pages to keep search rankings.
